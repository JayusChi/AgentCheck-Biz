## 本轮修复的交付问题

原恢复页绑定本机 D30 历史报告；新入口从当前 CI 恢复套件生成经摘要绑定的索引，并使用独立业务历史目录。平台现可由原控制器响应停止请求，避免用磁盘 PID 杀进程。

新环境实测发现两处可复现问题：全局 Python 的旧 .pth 编码使强制 UTF-8 启动失败，现用隔离的 `-I -S -m venv` 创建环境；源码白名单漏带 D34 源码摘要需要的 requirements.txt，现已补齐。网络沙箱导致的一轮依赖下载失败独立保留。所有失败记录未删除。第四个新环境完成安装和原核心验收后，演示编排还检出了预期FAIL被通用自测包装器误判为异常的问题；新增独立门禁状态处理及3项反例测试，再在本轮新建环境内用全新输出重跑完整验收通过。没有复用所有者的旧虚拟环境或业务数据。
