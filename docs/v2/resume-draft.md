# 项目经历草稿

**AgentCheck-Biz：基于 AgentCheck 的业务结果验证扩展**

- 设计执行、环境、观察和验证适配边界，接入自建 Ticket 与未修改的 Gitea，通过真实 MCP/HTTP 调用及独立业务观察检查重复副作用与错误完成声明。
- 构造提交后响应丢失、服务/Agent 崩溃窗口，使用 PostgreSQL 检查点、租约接管和持久化预算验证恢复；Ticket 使用原子幂等，Gitea 证据不足时保守停止。
- 建立固定场景、可追溯证据与回归门禁，将已知重复缺陷与正常候选区分；提供 Windows 核心回归、Linux 容器网络/恢复 CI 和可复现候选交付入口。

数字只按对应实测记录引用：D33 远程 Windows 为 202 项测试，Linux 为 3 个网络与 4 个恢复实验；D34 为 6 个真实模型槽位、16 次请求、11,038 已知 tokens。本轮 D35 测试数量与远程状态见 [D35 结果](d35-results.json)，不要混合相加成模型样本量。

历史数字依据：[历史证据索引](history.md)。归属：[UPSTREAM](../../UPSTREAM.md)。限制：受控单机实验，小样本不推广统计成功率；无生产可用性承诺；独立第三方试用待真实反馈。
